You can change the product and get answers about it without waiting for an engineer's time. Every change goes through a pull request an engineer reviews, so nothing goes live by accident.

<Note>
Examples use Claude Code on the web. In Codex, start with `$` instead of `/`.
</Note>

## Where to work

| You have | Do this |
|---|---|
| Nothing installed | Open [claude.ai/code](https://claude.ai/code) or [chatgpt.com/codex](https://chatgpt.com/codex), or either phone app. Pick the repository. [Full steps](/how-to/use-the-kit-from-the-browser) |
| No agent open | Fill in the **Request a change** issue form on GitHub. An agent picks it up and links the pull request on the issue |
| A Codex team | Assign the GitHub issue to Codex, or comment `@codex use request-a-change for this issue`. Mentioning `@Codex` in Slack or Linear works too, if connected |

Not sure which skill to use? Type `/start-here` and say what you want.

## Change the product

### Change text

```text
/request-a-change the onboarding headline should say "Plan your week in two minutes"
```

The agent restates the change and asks "Is that right?", updates every language the app supports with a real translation, takes before and after screenshots, and opens a pull request. You get the link and the screenshots. An engineer reviews and merges.

### Ask for a bigger change

Describe the outcome, not how to build it:

```text
/request-a-change users who skip onboarding should see a one-line tip on the home screen the first time
```

### Report a bug

```text
/request-a-change after changing the language to Vietnamese, the plan names still show in English
```

Say three things: what you did, what you saw, and what you expected. The agent reproduces it in the running app, finds the cause, and opens a fix with proof. If it cannot reproduce it, it tells you what it tried.

Teams with routines set up can have every new bug report reproduced automatically. See [Routines](/how-to/run-many-agents#routines).

<Warning>
Requests that touch money, permissions, personal data, or deleting things go to an engineer. The agent tells you when that happens.
</Warning>

## Get answers

| You want | Type |
|---|---|
| How something works today | `/how does the free trial end?` |
| Why it was built this way | `/why do we ask for a phone number at sign-up?` |
| Why a number changed | `/why did conversions drop after the pricing page change?` |
| A step-by-step explanation | `/teach me how notifications get to a user's phone` |
| The last answer in plain words | `/bro` |

`/why` digs through pull requests, commits, issues, and any other sources your agent is connected to.

## Write and summarize

| You want | Type |
|---|---|
| Release notes or a structured document | `/technical-writing draft release notes for everything merged this week` |
| Remove the tells of machine-written prose | `can we unslop this announcement?` |
| A summary of your own recent work | `/what-did-i-get-done this week` |
| A weekly summary of the whole team's work | `/weekly-review for every author on main` |

## Learn

```text
/create-learning-path I want to understand our analytics events well enough to add one
```

Later, `/run-learning-retrospective` checks your progress and adjusts the plan.

## If something does not work

| You see | What it means | Who fixes it |
|---|---|---|
| The agent does not know `/start-here` | The kit does not load in this cloud environment | An engineer, with `/setup-cloud-agents` |
| No screenshots, only test results | The repository has no verification skill, or the app cannot run in the cloud | An engineer, with `/create-verification-skill` |
| The agent cannot open a pull request | Your GitHub connection lacks access | Reconnect GitHub, or ask a repository admin |
| Codex finished but there is no pull request | In Codex, you open it | Press the button on the task |
| Codex says something it needs is blocked | Codex cloud tasks have no internet access | An engineer checks the environment |
