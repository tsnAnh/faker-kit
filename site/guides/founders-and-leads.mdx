Everything here works from [claude.ai/code](https://claude.ai/code), [chatgpt.com/codex](https://chatgpt.com/codex), or either phone app, with nothing installed. [How to start](/how-to/use-the-kit-from-the-browser).

<Note>
Examples use Claude Code. In Codex, start with `$` instead of `/`.
</Note>

## Know what shipped and why

| You want | Type |
|---|---|
| A week of work, grouped into bug fixes, tech debt, and new work | `/weekly-review for every author on main, not just me` |
| The reason behind a decision | `/why did we move payments to a separate service?` |
| A plain explanation of a system | `/teach me how the sync engine works, as if I were a new engineer` |
| An answer in plainer words | `/bro` |

`/weekly-review` covers only your own commits unless you ask for every author. To get it every Friday without asking, have an engineer add the weekly routine with `/setup-routines`. It posts the review as a GitHub issue.

## Measure how much you can trust agents

```text
/trust-audit
```

It scores the repository from 0 to 3 on each layer of [the trust ladder](/explanation/trust-ladder), with evidence for each score. It lists the five fixes that would help most, and says how many agents can safely work in parallel. Each audit is logged in `.agents/trust-audit.tsv`, so you can watch the scores rise.

| Where the repository is | Safe number of agents |
|---|---|
| Agents cannot run the app and check their work | 1 to 5, each watched by a person |
| Every layer at 2 or more | 10 to 30, in cloud sessions, each opening its own pull request |
| Every layer at 3, checks under 15 minutes, both review bots on | 100 or more, through routines and autopilot playbooks |

The lowest layer sets the limit. Fix the top items before raising the number. [Why](/explanation/scaling-agents).

## Let anyone on the team ship safely

Designers, marketers, and you can change the product with `/request-a-change`. The safety comes from the gates, not the person:

<Steps>
  <Step title="Every change is a pull request">
    No agent merges on its own.
  </Step>
  <Step title="It passes the same checks">
    One `scripts/check.sh` that CI runs on every pull request.
  </Step>
  <Step title="Claude and Codex review it">
    An engineer sets this up with `/setup-review-bots`.
  </Step>
  <Step title="A code owner approves it">
    The [branch protection checklist](https://github.com/tsnAnh/faker-kit/blob/main/plugins/trust-ladder/templates/branch-protection.md) makes this a rule.
  </Step>
</Steps>

Then an engineer runs `/setup-cloud-agents`, so the rest of the team works from a browser with nothing installed. `/trust-audit` tells you whether it works yet. [Why non-engineers can ship safely](/explanation/why-non-engineers-can-ship-safely).

## Turn review feedback into rules

```text
/style-guide-from-reviews last 90 days
```

It reads the team's pull request comments, finds the feedback reviewers keep repeating, and writes it into STYLE.md with an example of each. Each entry names the stronger layer it should move to, such as a lint rule. Engineers then run `/correct` to move it there.

## Roll it out

| Week | What happens |
|---|---|
| Week 1 | An engineer sets up the main repository: `/setup-team-kit`, review bots, branch protection, `/create-verification-skill`, `/setup-cloud-agents`, `/setup-routines`, and a first `/trust-audit` |
| Week 2 | Engineers install the kit. Everyone else gets a seat on the team's Claude or ChatGPT plan, connects GitHub, and starts with a small, visible task such as a copy change |
| Monthly | `/trust-audit` and `/style-guide-from-reviews`. Decide whether to raise the number of agents |

Roles to assign:

| Role | Who | Does |
|---|---|---|
| Gardener | One engineer, rotating monthly | Reads the gardener report and stops spreading bad patterns |
| Verification-skill owner | One engineer | Keeps the skill that runs the app working |
| Code owners | Per area | Review and merge pull requests, including those from non-engineers |
| Kit maintainer | One engineer | Updates the kit and its models |
| Bot owners | One Claude Code user, one Codex user | Run the review bots and routines on their plans |

Numbers to watch:

| Number | Healthy direction |
|---|---|
| Share of corrections in layers 1 and 2 | Up |
| The same rule corrected twice | Zero |
| Trust score per layer | Up, with the lowest layer rising |
| Time for `scripts/check.sh` | Under 15 minutes |
| Pull requests merged with verification evidence | Up, toward all of them |
| Requested changes from non-engineers, and days from issue to merge | Count up, days down |
