By the end of this hour, a repository is set up for agents, an agent has shipped a change with proof that it works, and one of your corrections is enforced by CI instead of living in a chat.

<Steps>
  <Step title="Install the kit (5 minutes)">
    <Tabs>
      <Tab title="Claude Code">
        ```text
        /plugin marketplace add tsnAnh/team-kit
        /plugin install trust-ladder@team-kit
        ```
        This also installs the eight plugins it depends on. `claude plugin list` shows all nine.
      </Tab>
      <Tab title="Codex">
        ```bash
        codex plugin marketplace add tsnAnh/team-kit
        for p in trust-ladder pstack team-workflows thermos continual-learning cli-for-agent agent-compatibility advisor teaching; do
          codex plugin add "$p@team-kit"
        done
        ```
        At the first start, type `/hooks` and trust the team-kit hooks.
      </Tab>
      <Tab title="Pi">
        ```bash
        pi install git:github.com/tsnAnh/team-kit@<commit sha>
        ```
        pstack's skills also need the `pi-subagents` and `pi-ask-user` packages.
      </Tab>
    </Tabs>
    Check it: type `/start-here` (`$start-here` in Codex, `/skill:start-here` in Pi). The agent should ask what you want to do.
  </Step>
  <Step title="Set up a repository (20 minutes)">
    The repository must build and pass its tests first. On a new branch:
    ```text
    /setup-team-kit
    ```
    It opens one pull request with AGENTS.md, a single `scripts/check.sh` that runs everything CI runs, a lint pack for each stack it finds (with a baseline so only new violations fail), review-bot instructions, and team settings for all three agents. Merge it.
  </Step>
  <Step title="Build a verification skill (20 minutes)">
    ```text
    /create-verification-skill
    ```
    A small CLI that starts your app, drives it, and captures screenshots, logs, and traces. Without it, agents can only guess whether their change works, and you stay the bottleneck. For mobile apps it builds on `/control-mobile`.
  </Step>
  <Step title="Ship one change with proof (15 minutes)">
    ```text
    /faker-mode add an empty state to the search screen. verify it really works.
    ```
    `/faker-mode` picks a playbook (here, Feature), hands work to subagents, runs your verification skill, and opens a pull request with the evidence. It stays on for the session; say "exit faker mode" to stop.
  </Step>
  <Step title="Correct the agent once, for good">
    The next time an agent does something you do not want repeated:
    ```text
    /correct the agent keeps catching Exception and swallowing it
    ```
    It fixes the mistake at the highest level that works (architecture, then types, a lint or CI check, a test, and docs last), proves the new check fails on a real past mistake, and adds the rule to the table in AGENTS.md.
  </Step>
</Steps>

## Finish the setup

Do these once, after the setup pull request merges:

| Run | Why |
|---|---|
| `/setup-review-bots` | Claude and Codex review every pull request, with no API keys |
| [Branch protection checklist](https://github.com/tsnAnh/team-kit/blob/main/plugins/trust-ladder/templates/branch-protection.md) | Required checks, resolved threads, and a code owner's approval. This is what makes it safe for anyone to open pull requests |
| `/setup-cloud-agents` | The repository boots in a fresh cloud session, so agents run in parallel and non-engineers need nothing installed |
| `/setup-routines` | Nightly upkeep and weekly reports run on a schedule |
| `/trust-audit` | A score per layer. Keep the first row as your baseline |
